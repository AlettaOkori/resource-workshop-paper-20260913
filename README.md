# 资源工坊 · 纸面编排

这是基于 `hzt-demo-final-0911` 的独立可运行副本，整体 UI 采用 `visual-studies-20260912/02-paper.html` 的纸面编排方案。老原型目录没有被覆盖。

## 启动

在当前 Mac 上，双击本目录的 **START-Mac.command**。启动后打开：

**http://127.0.0.1:4314**

终端里按 `Ctrl+C` 停止。脚本优先使用系统 Node；当前机器没有系统 Node 时，会自动使用已存在的 Codex Node 运行环境。

已安装 Node.js 24 或更新版本时，也可以运行：

```sh
cd "/Users/alettaokori/Work/K12/AI资源工坊/resource-workshop-paper-20260913"
npm start
```

`npm run dev` 与 `npm start` 均启动这个完整的独立应用。已带上老原型所需的 standalone 依赖，不需要重新安装或构建。不要直接运行 `server.js`，那会绕过新增视觉层。

更换端口：

```sh
PORT=4320 node start.mjs
```

默认仅监听本机 `127.0.0.1`。启动器同时管理一个内部随机端口上的原应用进程，退出时一并停止。新版运行不依赖老原型服务器。

**原业务运行文件完整保留。** 原目录仅提供已构建的 Next.js standalone 应用，没有可编辑的业务源码工程，因此保留全部原运行文件，并以独立展示层应用新视觉。此次按用户要求在该层新增个人资源归集功能：

- `start.mjs`：本地启动及转发。仅给应用 HTML 加载展示层；原请求路径、方法、正文、Cookie 和 Host 保留，RSC 与 API 正常转发。
- `paper-theme/paper.css`：全局、导航、首页、书册、附件与触屏样式。
- `paper-theme/secondary.css`：知识库、广场、看板、图谱、详情与聊天样式。
- `paper-theme/presentation.js`：负责视觉标记、装饰角色，并加载独立的个人资源模块。
- `paper-theme/my-resources.js`、`my-resources.css`：统一资源分类、详情状态、创作归档、教师自定义分组和响应式界面。
- `paper-theme/resources/catalog.json`：从原资源列表和知识库提取的 12 项原有资源索引，保留原内容地址。
- `paper-theme/assets/`：方案 2 的书册封面。仅改变首页封面的呈现，原图片地址、作品内容和链接保留。
- `.next/`、`node_modules/`、`public/`、`server.js`：完整保留原运行文件。作品 iframe 内的教学内容、脚本、交互及语义颜色保持原样。

除本次明确要求的个人资源功能外，原型本来的模拟、占位与失败边界保持原样：

- 生成流程使用原型已有的模拟任务与预置历史，未新增在线 AI 服务。完成作品的索引、收藏状态和资源分组现在会在当前浏览器保存。
- 广场快速搜索及部分全局或详情按钮仍保留原型占位行为。「我的资源」内的搜索、筛选、收藏、点赞和关注已实现实际处理。
- 详情“下载”原本只显示加入队列提示；聊天 HTML 下载可以产生本地文件，DOCX 仍使用原外部链接。
- 两条知识库历史分享 ID 原本缺少离线数据，现在在「我创作的」保留其标题并链接到对应的原历史会话。唐诗图谱的分享 iframe 原本有 `Invalid URL` 错误，作品文件保持原样。

具体操作和差异见 [验收报告](verification/ACCEPTANCE.md)、[原页面基线](verification/original-pages.md) 与 [原创作基线](verification/original-creation.md)。

## Netlify 部署（2026-09-14）

GitHub 仓库保存当前新版原型及其独立运行文件。`netlify.toml` 使用 `hosting/` 作为构建目录，执行 `npm run build`；公共素材、新版样式和 Next.js 客户端文件由 CDN 提供，页面与 RSC 请求由 `hosting/functions/workshop.js` 转给原 standalone 运行层。

由于当前交付物没有原始 Next.js 业务源码，`runtime/node-modules.tar.gz` 保存已有运行依赖。新机器本地启动前，在仓库根目录执行 `tar -xzf runtime/node-modules.tar.gz`，然后使用 Node.js 24 运行 `npm start`。不要对根目录执行 `npm install` 来替换原构建依赖。部署构建只使用 Node 内置模块，不重新安装原应用。

修改 `paper-theme/` 或公共素材后，提交并推送 `main`，Netlify 将自动部署。原型依旧使用演示生成流程，个人资源与分组保存在各访客浏览器本地，不跨设备同步。

`verification/` 是本机历史验收资料，未上传到仓库；本 README 中相关历史链接仅在原工作目录可用。
