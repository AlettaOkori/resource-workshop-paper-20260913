这是基于 `hzt-demo-final-0911` 的独立可运行副本，整体 UI 采用 `visual-studies-20260912/02-paper.html` 的纸面编排方案。老原型目录没有被覆盖。

## 启动

在当前 Mac 上，双击本目录的 **START-Mac.command**。启动后打开：

**http://127.0.0.1:4314**

终端里按 `Ctrl+C` 停止。脚本优先使用系统 Node；当前机器没有系统 Node 时，会自动使用已存在的 Codex Node 运行环境。

已安装 Node.js 24 或更新版本时，也可以运行：

```sh
cd "/Users/alettaokori/Work/K12/AI资源工坊/resource-workshop-paper-20260913"
npm start
```

`npm run dev` 与 `npm start` 均启动这个完整的独立应用。已带上老原型所需的 standalone 依赖，不需要重新安装或构建。不要直接运行 `server.js`，那会绕过新增视觉层。

更换端口：

```sh
PORT=4320 node start.mjs
```

默认仅监听本机 `127.0.0.1`。启动器同时管理一个内部随机端口上的原应用进程，退出时一并停止。新版运行不依赖老原型服务器。

2026-09-13，按用户明确要求扩展个人资源功能：

- 首页「我的资源」统一展示书本资源，第一排保留高低编排，第二排起采用 1:1 正方形书本封面并整齐对齐；通过「更多我的资源」进入同一模块；侧栏增加「我的资源」。原知识库入口统一进入「我创作的」，原有 10 项资源和 2 项历史创作均保留。
- 支持关键词、资源类型、最近收录/名称排序及网格/列表视图。收藏和点赞可在卡片、详情页同步操作；新完成作品自动收录。
- 用户澄清「文件夹」是老师组织现有资源的分组，并要求重做交互。当前为常驻分组栏 + 资源列表工作区；在同一页面切换全部、未分组和自定义分组。
- 新建和重命名在分组栏内输入，分组菜单提供重命名和删除。桌面可将资源或多选资源直接拖入分组；手机通过卡片勾选和底部批量操作栏归组。卡片上的分组按钮提供就近菜单，并可直接创建分组后加入。

- 同一资源可属于多个分组，四类筛选和计数对应当前分组。加入、移出、批量移出和删除分组提供 8 秒内撤销；操作不会删除资源或取消其收藏、关注、点赞状态。
- 资源状态和分组使用 localStorage 键 `resource-workshop.library.v1`；分组记录为 `groups: [{id, name, resourceIds, createdAt}]`，仅保存资源引用。兼容更新前已有的收藏、点赞、关注和创作记录。刷新后保留；不同浏览器、设备或端口不共享，清除站点数据会删除这些本地记录。未接入云端存储。

已撤下先前误解产生的本地文件夹上传、导入和文件浏览功能；原知识图谱「文件夹」入口仍归并到个人资源模块。旧的 `view=folders`、`view=groups` 链接都进入同一工作区。此次没有删除先前版本可能写入的 IndexedDB 数据，也不将本地文件冒充资源分组；当前模块不再读取或写入该文件库。

## Netlify 部署（2026-09-14）

GitHub 仓库保存当前新版原型及其独立运行文件。`netlify.toml` 使用 `hosting/` 作为构建目录，执行 `npm run build`；公共素材、新版样式和 Next.js 客户端文件由 CDN 提供，页面与 RSC 请求由 `hosting/functions/workshop.js` 转给原 standalone 运行层。

由于当前交付物没有原始 Next.js 业务源码，`runtime/node-modules.tar.gz` 保存已有运行依赖。新机器本地启动前，在仓库根目录执行 `tar -xzf runtime/node-modules.tar.gz`，然后使用 Node.js 24 运行 `npm start`。不要对根目录执行 `npm install` 来替换原构建依赖。部署构建只使用 Node 内置模块，不重新安装原应用。

修改 `paper-theme/` 或公共素材后，提交并推送 `main`，Netlify 将自动部署。原型依旧使用演示生成流程，个人资源与分组保存在各访客浏览器本地，不跨设备同步。

`verification/` 是本机历史验收资料，未上传到仓库；本 README 中相关历史链接仅在原工作目录可用。
